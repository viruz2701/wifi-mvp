# Разделение трафика при использовании WireGuard

При использовании WireGuard для управления NAS важно, чтобы трафик гостевых клиентов Wi-Fi не проходил через туннель, а использовал обычный интернет-шлюз. В то же время трафик управления (RADIUS, SSH, API) должен идти через туннель к серверу.

## Общий принцип

1. На сервере (бэкенде) настроен WireGuard интерфейс (например, `wg0`) с подсетью `10.0.0.0/24`.
2. Каждое NAS-устройство получает IP из этой подсети и устанавливает туннель с сервером.
3. На NAS необходимо настроить policy routing, чтобы:
   - Трафик, предназначенный для сервера (IP бэкенда), направлялся через интерфейс WireGuard.
   - Весь остальной трафик (в том числе гостевой) шёл через стандартный шлюз (например, через WAN).

## Пример настройки для MikroTik

Предположим, сервер имеет IP в туннеле `10.0.0.1`, NAS — `10.0.0.2`. Адрес сервера в локальной сети (для доступа к RADIUS) может быть, например, `10.10.10.10`.

### Создание routing table для туннеля
/ip route rule
add src-address=10.0.0.2/32 table=wg
/ip route
add dst-address=10.10.10.10/32 gateway=10.0.0.1@wg table=wg

text

Теперь весь трафик от NAS к серверу пойдёт через WireGuard. Остальной трафик остаётся в основной таблице маршрутизации.

### Настройка NAT для гостевого трафика

Обычно NAT уже настроен для интерфейса, который смотрит в интернет. Убедитесь, что для трафика, выходящего через основной шлюз, NAT работает.

## Пример для OpenWrt

В OpenWrt можно использовать `ip rule` аналогично, либо настроить политики через `luci`.

## Важно

- Не забудьте открыть порты WireGuard на файерволе сервера.
- Убедитесь, что сервер имеет статический IP (или динамический DNS) для подключения NAS.
